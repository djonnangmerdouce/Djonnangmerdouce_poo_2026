# TP2 : Encapsulation et Validation des donnéesCe projet améliore l'architecture du gestionnaire IPPlan-Manager en introduisant des mécanismes de protection des données réseau. 
 # Réponses détaillées aux questions de compréhension
1. Pourquoi utilise-t-on private dans les classes ?
Le mot-clé private est le pilier de l'encapsulation. Il permet de masquer l'implémentation interne d'un objet (ses attributs) pour que personne ne puisse les modifier de l'extérieur. Cela évite qu'une autre classe ne vienne corrompre les données, comme mettre une adresse IP à "vide" par erreur. 
 2. Quelle différence existe entre un attribut public et un attribut privé ?Attribut Public : Il est "ouvert" à tous. N'importe quelle partie du programme peut modifier ip.valeur sans contrôle, ce qui peut mener à des incohérences ou des pannes logiques.  Attribut Privé : Il est "protégé". Seule la classe elle-même peut y accéder. Pour le modifier ou le lire, il faut obligatoirement passer par des "portes d'entrée" officielles (getters/setters).  3. Pourquoi utilise-t-on des getters et setters ?Getter (Accesseur) : Il permet de consulter la donnée sans risquer de la modifier accidentellement.  Setter (Mutateur) : C'est le "gardien" de la donnée. Il intercepte la nouvelle valeur et vérifie si elle est correcte avant de l'attribuer à l'objet. Par exemple, si on essaie de mettre un nom vide à un équipement, le setter peut décider de mettre "equipement inconnu" à la place.  4. Pourquoi les validations sont-elles importantes dans un logiciel réseau ?
Dans le domaine des réseaux et télécommunications, une simple erreur de saisie (adresse IP mal formée, masque erroné) peut provoquer des conflits d'adresses, des erreurs de configuration critiques ou des comportements imprévisibles sur les équipements réels. La validation garantit que le logiciel reste robuste et fiable. 
 5. Quel est le rôle du mot-clé this ?this fait référence à l'instance courante de l'objet. Il est indispensable quand le nom du paramètre reçu par une méthode est identique au nom de l'attribut de la classe (ex: this.nom = nom;). Il permet de dire à Java : "Prends la valeur du paramètre nom et mets-la dans l'attribut nom de cet objet précis". 
 6. Pourquoi le constructeur appelle-t-il les setters ?
Plutôt que d'écrire deux fois les mêmes règles de vérification (une fois dans le constructeur et une fois dans le setter), on appelle le setter directement dans le constructeur. Ainsi, dès la création de l'objet, les données sont validées automatiquement. Si l'utilisateur tente de créer un objet avec des données fausses, les valeurs par défaut (comme 0.0.0.0 pour une IP) sont appliquées immédiatement.  7. Pourquoi la validation du masque CIDR est-elle importante ?
Le masque CIDR définit la taille d'un réseau et doit techniquement être compris entre 0 et 32. Si on autorise un masque comme "45", tous les calculs de sous-réseau deviendront faux. Le TP force donc un masque invalide à revenir à une valeur standard comme 24 pour maintenir la cohérence du système. 
 8. Pourquoi l'encapsulation améliore-t-elle la sécurité logicielle ?
L'encapsulation réduit la "surface d'attaque" des erreurs. En isolant les données, on s'assure qu'aucune modification non autorisée ou incohérente ne peut être faite. Cela rend le code plus facile à maintenir et à faire évoluer, car on sait exactement où les données sont contrôlées.
